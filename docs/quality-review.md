# Usability and functional review

This review covers the single-workspace StockSense application. All automated mutations run in the guarded `stocksense_test` database. The existing demo database and unrelated billing project are not reset by these tests.

## Findings and corrections

| Question raised during review                                    | Finding                                                                                                        | Correction                                                                                                                                                                               |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Can a warehouse operator read the interface comfortably?         | Many labels and values were 9-12px, with weak contrast.                                                        | Locally hosted Inter, 14-15px primary UI text, 28-32px page headings, larger controls, darker secondary text. | Are the important actions clear?                                 | Small buttons and subtle table links were difficult to target.                                                 | Larger primary actions, stronger create/confirm/validate buttons, outlined row-open controls, sticky operation actions on desktop.                                                       |

## Evidence and boundaries

Run `npm test` and `npm run test:e2e` sequentially. The API tests use real PostgreSQL transactions and local SMTP. Browser tests use Chromium with separate app processes on ports 3002/5174. The test-case PDF records the final executed results and maps its scenarios to individual automated tests. A case catalog is not a claim that every possible input or environment has been exhausted.

Automated accessibility checks cover WCAG 2 A/AA and 2.1 AA rules exposed by axe on selected screens. This is not an accessibility certification or a substitute for manual screen-reader testing. Responsive viewport checks are not physical-device testing. Print testing verifies the print action and rendered print layout; physical printers are not exercised.

Gmail credentials are supplied locally by the owner. Until configured and checked, external inbox delivery is unverified. Tests intentionally never send mail through Gmail. No paid service, credit card, or usage-billed API is introduced.

The app supports one shared inventory workspace with two permission roles and many user accounts. It does not implement tenant isolation, warehouse-specific user permissions, partial deliveries/backorders, procurement approvals, lots/serials, accounting, billing, taxes, payments, or scheduled production backups. These are scope boundaries, not passed tests. The inventory ledger is immutable through the application API; database administrators retain direct database access. Auth throttles are local to one API process and reset on restart. Public production deployment and its operational controls require a separate review.
